# NorthLink · Windows 点对点端口映射

**v0.1.0 / 第一版 / Windows 10 x64**

提供端与客户端均为中文 WPF 图形界面，支持托盘、配置、退出。使用 Redis 交换信令，以 ICE / STUN 发现并检查直连路径，在同一 ICE UDP 通道上建立 QUIC，转发提供端发布的 TCP 服务。**没有 TURN、Redis 业务转发或其他中转回退。**

> 这是已编译、具有实际网络实现的首版，不是演示界面。开发环境的本地链路验证已通过，但未在真实 Win10 桌面、Windows 服务管理器或你的跨网 NAT 环境中运行验证。不保证所有 NAT 组合都能直连，也没有给出带宽/延迟的实测承诺。

## 下载包中运行什么

完整解压 `NorthLink-Win10-x64.zip`，不要从压缩包内直接运行，也不要单独复制 EXE。

- `NorthLink.Provider.exe`：提供端（你说的服务端），放在网站、远程桌面所在的电脑。
- `NorthLink.Client.exe`：客户端，放在需要访问服务的电脑。
- `northlink-core.exe`：隐藏运行的网络核心，界面自动管理，无需双击或手工命令行。
- 其余 DLL / JSON：自包含 .NET 桌面运行时及应用文件，不要删除。
- `NorthLink-Guide.html`：离线中文使用指南。
- `THIRD-PARTY-NOTICES.txt`：第三方组件许可。

便携包包含 .NET 8 桌面运行时，无需另装 Go 或 .NET。推荐 Win10 22H2 64 位；不包括 32 位或 ARM64 成品。程序未做发布者代码签名。请核对随包提供的 SHA-256 清单，不要在不信任来源时运行。

## 五步开始

### 1. 两端配置 Redis

在“连接配置”中填写同一 Redis 主机、端口、数据库 DB、用户名（可选）和密码。主机只填域名或 IP，不带 `redis://`。TLS 实例勾选“Redis 使用 TLS”。

两端的 **连接组** 也必须一致，默认 `default`。设备名称可自定义，设备 ID 首次启动时自动生成并持久保存。

Redis 要求：单实例 Redis 5.0+，允许以下命令及程序自己的 `northlink:v1:*` 键：

`PING`、`AUTH/HELLO`（按实例）、`SELECT`（非零 DB）、`SET`、`GET`、`SCAN`、`DEL`、`EXPIRE`、`XADD`、`XREAD`。

启动时会检查实际信令命令；不满足 Streams / ACL 要求会明确报错。本版没有 Redis Cluster / Sentinel 专用配置。

### 2. 提供端发布服务

默认已有两条可编辑的服务：

| 名称 | 目标 |
|---|---|
| 网站 | `127.0.0.1:80` |
| 远程桌面 | `127.0.0.1:3389` |

也能填写提供端可以访问的其他内网 IP 和 TCP 端口。确认勾选启用，点击“保存并应用”，再“启动连接”。**目标服务必须本来就在运行，本工具不会安装网站或开启 Windows 远程桌面。**

### 3. 客户端添加本地映射

客户端启动连接后，进入“端口映射”：选择在线提供端 → 选择服务 → 添加映射 → 确认本地端口 → 保存并应用。

默认网站使用 `18080`，远程桌面使用 `13389`。端口冲突时修改为其他未占用端口。

### 4. 查看直连状态

“连接工作台”分别显示 Redis 信令状态、P2P 会话状态、RTT、连接数和流量。映射表显示监听状态和最近一次目标连接结果；悬停错误行可查看详情。

Redis 在线不等于 P2P 已直连，P2P 已直连也不等于目标端口已打开。

### 5. 访问服务

- 浏览器访问 `http://127.0.0.1:18080`。
- Windows 远程桌面连接 `127.0.0.1:13389`，使用提供端 Windows 的登录凭据。
- 新增的其他 TCP 服务，连接其对应本地地址即可。

默认只监听 `127.0.0.1`，供本机应用使用。确实要允许客户端所在局域网的其他设备访问时，可自行改为相应网卡 IP 或 `0.0.0.0`，并处理客户端 TCP 入站防火墙。

## STUN 默认列表

```
stun:stun.hitv.com:3478
stun:stun.miwifi.com:3478
stun:stun.xten.com:3478
stun:stun.voip.aebc.com:3478
```

首项已按要求改为 `stun.hitv.com`。这些地址是用户指定的预置候选，**没有验证它们当前的在线状态或各自服务端口**。3478/UDP 是预填值，可在界面修改。多个节点并行收集，收到候选后交由 ICE 选择可用直连路径，不保证最后选用列表第一项。STUN 没有业务中转功能。

如果日志提示“未取得 STUN 映射”，程序仍会尝试内网/可达 IPv6 候选，但跨 IPv4 内网通常需要有效的 STUN 映射。不要把旧 Redis TCP 外网端口当作 UDP 候选。

## 托盘、开机与无人值守

- 点窗口 X：隐藏到托盘，继续运行。
- 托盘“打开主界面”“连接配置”：恢复界面。
- “停止连接”：断开业务会话、释放本地监听，保留程序。
- “停止并退出”：请求核心停止，并退出界面。
- 登录自启与软件启动后自动连接是两个独立选项，按需一起勾选。

提供端“连接配置 → 无人值守运行”支持安装、启动、移除 Windows 服务，操作会请求管理员权限。安装时使用当前配置和程序的绝对路径，并启用系统自动/延迟启动及故障恢复。服务启动后自动尝试连接 Redis，失败每 10 秒重试。

安装服务后：

1. **不要移动、重命名或删除程序目录**；需要移动/升级时先移除服务。
2. 托盘新增“退出界面（保留无人值守服务）”，适合长期远程桌面使用。
3. 安装记录与配置按当前 Windows 用户区分。建议使用安装时的同一用户管理；其他 Windows 用户有独立的配置与界面实例。
4. 修改配置会重建连接；首次安装/移除服务也会断开当前会话。
5. 普通托盘模式在用户注销时不能保证继续运行；无人值守服务模式用于尚未登录和注销后的后台运行。

## 防火墙

两端都需要能够访问 Redis，以及向 STUN 和对端动态 UDP 地址/端口发送、接收数据。**只开放 STUN 的 3478 端口并不足够。**

“放行程序 UDP（管理员）”为当前 `northlink-core.exe` 添加 Windows Defender 防火墙 UDP 入站允许规则（所有配置文件）。不会修改路由器，也无法绕过企业网策略。无需配置路由器端口映射才能尝试打洞，但打洞本身不保证成功。

## 错误处理

| 现象 | 优先检查 |
|---|---|
| Redis 连接失败 / WRONGPASS | 地址、端口、密码、ACL 用户、TLS、DB；无需把密码发给他人 |
| 信令命令检查失败 | Redis 是否为 5.0+，是否允许 Streams、SCAN 和程序键前缀 |
| 客户端看不到提供端 | 两端 Redis / DB / 连接组是否一致，提供端是否启动；等待约 5 秒刷新 |
| 无 STUN 映射 | 域名、实际服务端口、UDP 出站、公共 STUN 是否可达 |
| 已发现对端但直连失败 | 严格 NAT、封 UDP、Windows 防火墙；两端网络是否允许直连 |
| 本地监听失败 | 本地端口被占用，或者绑定的网卡 IP 不存在 |
| P2P 已直连，目标服务失败 | 提供端服务是否启动、目标 IP/端口是否正确、目标防火墙 |
| 网页返回 404 或跳转到原地址 | 网站 Host 绑定、绝对重定向、HTTPS 证书；本工具不改写 HTTP |
| 远程桌面失败 | Win10 版本是否支持 RDP 主机，是否已开启远程桌面，账号是否有权限 |
| 服务未就绪 | 在提供端配置页点击“启动服务”，或查看 Windows 服务及 `core.log` |

不要因为某次失败就断言 NAT 类型；界面只报告已观察到的阶段和错误。

## 配置与日志

- `%LOCALAPPDATA%\NorthLink\provider\config.json`
- `%LOCALAPPDATA%\NorthLink\client\config.json`
- 同目录 `core.log` / `core.log.1`：轮转日志，各约 4 MiB 上限。
- 界面最近 250 条事件可导出。
- 配置以明文保存，包括 Redis 密码。导出配置同样包含密码。
- 导入配置保留当前机器的设备 ID，避免复制出两个相同身份的客户端。
- 不要手工复制运行中的 `config.json` 到其他机器；请用界面导入/导出。

## 当前范围与限制

- TCP 端口映射。RDP 第一版走 TCP；没有原生业务 UDP 映射。
- 不实现 UPnP、复杂端口预测、TCP simultaneous-open 或任何中转。
- 同一 QUIC 连接中的流独立排序，但共享拥塞控制与带宽，没有硬实时优先级保证。
- 断线自动重建链路；已断 TCP 会话需由浏览器/RDP 等应用重连。
- Redis 中断后，已经建立的 P2P 链路可继续传输；新打洞和发现受影响。
- 普通 Win10 远程桌面不因此获得多人独立并发会话能力。
- 连接组不是权限隔离系统。按需求未实现多用户授权、审计管理等生产安全功能。
- QUIC 自带 TLS，并校验通过信令交换的证书指纹；未使用系统原生 System.Net.Quic。
- 公共 STUN 可用性、不同 NAT 环境及真实性能须在实际部署环境确认。

## 源码构建

需要 Go 1.27.2（`go.mod` 固定）和 .NET 8 SDK。Windows PowerShell 中运行：

```powershell
.\build.ps1
```

输出 `build\win` 和 `build\NorthLink-Windows-x64.zip`。默认自包含，支持 `-Architecture x86` 自行构建 32 位；`-FrameworkDependent` 生成需要另外安装 .NET 8 Desktop Runtime 的小体积版本。

```powershell
cd core
go test -race ./...
go vet ./...
```

Windows 上运行 Go race detector 通常需要 C 编译器；普通编译 `CGO_ENABLED=0` 不需要。测试只使用本地临时 Redis/STUN 和本地目标服务，不连接预置公共 STUN 或用户 Redis。

详细协议见 `docs/ARCHITECTURE.md`，验证范围见 `docs/VALIDATION.md`。业务源码采用 MIT；第三方组件各自遵循随包许可证。
