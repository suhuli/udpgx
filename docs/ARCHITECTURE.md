# 当前原生版架构

## 数据与控制面

Redis 只保存设备短期在线状态、服务信息和会话信令。设备使用 Streams 交换 offer、answer、增量候选及拒绝信息。程序不向 Redis 写入用户业务数据。

每轮 ICE 协商创建 IPv4 / IPv6 UDP socket，候选发现与检查交错进行。IPv4 使用公共 STUN 获取反射地址，IPv6使用原生可用地址。候选中继类型及 TURN 配置被拒绝。旧版完整候选的兼容模式保留，但建议两端使用同一版本。

选定 ICE 路径之后，QUIC 通过同一 ICE UDP 通道进行 TLS 1.3 握手。临时证书的指纹经信令交换。每对设备保持一条 QUIC 连接，每个 TCP 连接占用一个双向流。流开头是长度受限的服务 ID 控制帧，提供端查找已启用服务、连接目标、返回确认，再双向转发字节。支持 TCP 半关闭。

## 生命周期

客户端为已启用映射维持预连接。会话有独立 ID，候选可增量补充；新会话可替换旧协商，过期回调不能覆盖新状态。失败采用 1–5 秒重试间隔。已建立的直连通常不受 Redis 暂时离线影响，新协商仍依赖信令。

原生界面与网络核心位于同一进程，由 `ipc.Controller` 在进程内控制配置、运行与停止；此处的包名不意味着当前 GUI 需要一个外置核心 EXE。`cmd/northlink-core`、Named Pipe 和 WPF 实现保留用于历史版本。

## 已知性能空间

当前并非“所有路径无限并发”：检查由 ICE 代理按其调度执行。信令写入仍存在同步等待；UDP mux 是每轮协商级别，而非跨协商的进程级 socket 池。QUIC 使用 ICE PacketConn 适配层，并非原生 UDP 快速路径。端口映射存在目标连接确认阶段。这些是后续优化方向，不能描述成已经完成。

当前没有 TCP 打洞、端口预测、UPnP/PCP、RDP UDP 映射或任何中转。严格 NAT、UDP 限制和防火墙可能导致完全无法直连。

## 凭据边界

公开源码的 `builtin_stub.go` 不含 Redis 账号。私有配置仅在显式私有构建时生成带 build tag 的文件。运行时解析内置配置，不把其凭据写回普通配置或导出数据。但持有 EXE 的人仍可能提取内置凭据；这不是强保密措施。
